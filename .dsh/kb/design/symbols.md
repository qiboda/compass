# 符号与股票代码

中国 A 股市场的股票代码并非全球唯一——同一数字代码在不同交换所可能
代表不同的东西。Compass 必须在保证数据模型足够简单、一个开发者即可
维护的前提下，处理这种歧义。

## A 股市场全景

中国有三家股票交换所，各自有不同的代码区间：

| 交换所 | 中文名称 | 市场代码 | 代码区间 | 重要板块 |
|---|---|---|---|---|
| Shanghai (SH) | 上海证券交易所 | `1` (EastMoney) | 600xxx–605xxx | 主板 |
| Shanghai (SH) | 上海证券交易所 | `1` | 688xxx | 科创板 |
| Shanghai (SH) | 上海证券交易所 | `1` | 900xxx | B 股（外币） |
| Shenzhen (SZ) | 深圳证券交易所 | `0` (EastMoney) | 000xxx–004xxx | 主板 |
| Shenzhen (SZ) | 深圳证券交易所 | `0` | 002xxx–003xxx | 中小板 |
| Shenzhen (SZ) | 深圳证券交易所 | `0` | 300xxx–301xxx | 创业板 |
| Beijing (BJ) | 北京证券交易所 | `0` (EastMoney) | 8xxxxx | 北交所 |

关键洞察：**对于股票而言，代码区间不会跨交换所重叠**。
`600xxx` 永远是上海，`300xxx` 永远是深圳，`8xxxxx` 永远是北京。
这意味着我们可以**从代码推断交换所**——无需在每行数据中额外存储这一信息。

> **注（stock_basic 数据源）**：`stock_basic` 元数据现来自三大交易所官网
> （SSE/SZSE/BSE），不再使用东财 push2 的 EM_FS 段位。东财 t:81 段混入的
> 4xx/9xx 新三板/老三板（NEEQ/OTC）代码不再出现于其中；北交所股票代码区间为
> 8xxxxx 与 92xxxx。

## 为什么选择 Dolt-native 符号？

Compass 将 Dolt-native 前缀格式（`"SZ000001"`、`"SH600519"`、
`"BJ830799"`）作为全局规范标识符：用于 `stock_daily.parquet` 的 `symbol` 列、
DuckDB 的 `symbol` 列，以及主键。输入层只接受带前缀的符号——裸 6 位代码
输入被禁止（D9），`sh.`/`sz.`/`bj.` dot 形式输入会被规范化为前缀形式。

旧格式 `"000001.SZ"`（ts_code 约定）已废弃。原因如下：

**ts_code 的问题**：将身份与元数据混在一起会制造歧义。
`"000001.SZ"` 编码了两个事实——股票是 `000001`，且在上海/深圳交易。
但交换所本身也可以从代码区间推断（见下文旧启发式）。
将其存入标识符是多余的，而冗余滋生不一致——万一有人误写成 `"000001.SH"` 呢？

**Dolt-native 符号带来的好处**：
- 无跨所碰撞：`SZ000852`（股票）和 `SH000852`（指数）由前缀区分——ref #201 起指数行已从
  `stock_daily.parquet` 剔除，指数行情独立入库 `index_daily.parquet`（epic #255），
  股票与指数分属不同文件、互不干扰
- 交换所一目了然：两位字母前缀立即可见（含 `BK` 板块前缀，见下文显式前缀）
- 格式更简洁：同一文件中所有标的由 `symbol` 列标识（指数/板块独立文件，见 epic #255）

`to_ts_code()` 辅助函数（`000001.SZ` 旧格式）已随 D9 从代码库移除——
不再有任何生产路径消费 ts_code 格式。

## 交换所推断：启发式规则（已废弃，D9）

> **⚠️ 已废弃（D9，issue #181）**：输入层不再接受裸 6 位代码，
> `to_exchange` 启发式函数已从代码库删除。下列规则仅保留作历史记录，
> 并以「D10 config 自动迁移规则」的形式继续存在——旧配置文件中的裸码
> 值按此规则补前缀（6→SH、8/43/92→BJ、其余→SZ；43 为北交所/新三板
> 代码段，与 8/92 同属 BJ，对齐官方采集器规则）。

给定一个裸六位代码，它属于哪个交换所？——这个问题的答案是：**不再需要回答**，
因为规范输入一律带前缀。以下是旧启发式的规则，按优先级排列：

| 代码以……开头 | 交换所 | 理由 |
|---|---|---|
| `6` | `"SH"` | 所有 6xxxxx 代码均为上海股票 |
| `8` | `"BJ"` | 所有 8xxxxx 代码均为北京股票 |
| 其他 | `"SZ"` | 000xxx–004xxx、002xxx、300xxx 均为深圳 |

该启发式规则对**股票**是正确的。指数则是另一回事。

## 歧义：000001

`000xxx` 区间是唯一一个代码跨交换所重叠的区间：

| 代码 | 交换所 | 是什么 |
|---|---|---|
| `000001` | 深圳 | 平安银行 — 股票 |
| `000001` | 上海 | 上证指数 — 指数 |
| `000002` | 深圳 | 万科A — 股票 |
| `399001` | 深圳 | 深证成指 — 指数 |

对于股票（99% 的使用场景），旧启发式规则将 `000xxx` 代码默认为**深圳**，
因为该区间几乎所有股票都在深圳交易——这正是该启发式不可靠的根源
（指数行 `000001` 会被误判为 SZ），也是 D9 弃用它的原因。

指数与股票的区分现在完全依赖**显式前缀**——裸码输入不再被接受：

| 输入 | 含义 |
|---|---|
| `SZ000001` | 平安银行（深市股票） |
| `SH000001` | 上证指数（沪市指数） |
| `sz.000001` | 平安银行（dot 形式，规范化为 `SZ000001`） |
| `sh.000001` | 上证指数（dot 形式，规范化为 `SH000001`） |

## 显式前缀

前缀是规范输入的唯一形式（D9 起不再有"无前缀默认"）——解析时通过前缀
强制指定交换所：

| 前缀 | 交换所 | 示例 | 结果 |
|---|---|---|---|
| `sh.` | 上海 | `sh.000001` | `"SH"`，`000001` |
| `sz.` | 深圳 | `sz.000001` | `"SZ"`，`000001` |
| `bj.` | 北京 | `bj.830799` | `"BJ"`，`830799` |
| `bk.` | 板块/指数 | `bk.0475` | `"BK"`，`0475` |

前缀**不区分大小写**：`SH.600519` 和 `sh.600519` 等效。

### 板块/指数前缀 `BK`（epic #255 + issue #283 D7）

板块使用**独立前缀命名空间** `BK` + 4-6 位数字：

- **4 位**：东财 BK 板块代码（`BK0475`），采集器零转换（已随 #283 停止采集，存量已清理）
- **6 位**：同花顺行业代码（`BK881101`，881xxx 申万一级 90 个，issue #283 D1）——
  `validate_symbol` 扩展为接受 `BK` + 4-6 位 ASCII 数字（`BK047` / `BK881` / `BKAB12`
  等畸形码一律拒绝，注入防线不削弱）。东财板块 1000 个采集目标已废弃（issue #281，
  2026-08-20 关闭），板块符号以同花顺 881xxx 行业为准，不再新增东财 BK 4 位。
- 规范形式：`BK0475` / `BK881101`（Dolt-native，无 dot）；解析规则与 SH/SZ/BJ 一致
  （`parse_explicit_prefix("BK881101")` → `("BK", "881101")`）
- `infer_exchange_prefix` 对 `BK` 天然返回 `None`（非 6 位裸码，不落入裸码启发式）；
  `exchange_of_symbol("BK881101")` → `"BK"`（原样返回，驱动 GUI 交易所 Tag 显示）
- 官方指数仍复用 `SH`/`SZ` + 6 位（`SH000001` 上证指数、`SZ399001` 深证成指）——与股票
  同格式，000xxx（沪）/399xxx（深）代码段与股票天然不重叠，无歧义；`index_type` 列
  （`official`/`industry`）在数据层区分两类标的（`concept` 类已随 #283 移除）

## 指数剔除约定（ref #201）

Dolt 源表 `final_a_stock_eod_price` 混入 6 个**指数代码**（非股票），`compass-data import`
在导出 `stock_daily.parquet` 与 `stock_daily.symbols.txt` 时无条件剔除：

| 指数代码 | 指数 |
|---|---|
| `SH000300` | 沪深300 |
| `SH000852` | 中证1000 |
| `SH000905` | 中证500 |
| `SH000906` | 中证800 |
| `SH000985` | 中证全指 |
| `SZ399300` | 沪深300（深市口径） |

剔除规则：
- **无条件生效**——即使 `--symbols` 显式指定某指数代码也剔除（防误选指数入评分）
- 主查询与 symbol 枚举查询均追加 `symbol NOT IN (...)`，parquet 与 symbols.txt 一致
- 指数与股票的同号碰撞（`SH000905` vs `SZ000905`）因剔除而自然消解：指数行不入库，
  股票行保留前缀独立存在（`run_preserves_colliding_sh_sz_symbols` 回归测试锁定此行为）

**指数独立入库（epic #255）**：剔除只作用于**股票管线**——自 epic #255 起，上述 6 个
指数中的 5 个（`SH000300`/`SH000852`/`SH000905`/`SH000906`/`SH000985`）已加入官方指数
白名单（`index_daily.rs::OFFICIAL_INDICES`，约 30 只主流指数），由东财 push2his
独立采集、以 `index_type='official'` 写入 `index_daily` 表，经 `import-compass` 导出
`index_daily.parquet`（股票管线剔除与指数独立入库并存，互不干扰）。`SZ399300` 为
沪深300 的深市口径重复码，**未入白名单**——其数据不单独采集（沪深300 以上交所
`SH000300` 为准）。`symbols.txt` 仍只含股票。

## EastMoney secid 映射

EastMoney 的 API 使用不同的标识符格式：`"{market}.{code}"`，其中
market 为 `0` 表示深圳/北京，`1` 表示上海。Compass 自身代码
从不构造 secid——GUI 仅本地访问，Rust 采集器也不使用此格式——
但此映射记录于此，供直接使用 EastMoney K 线 API 时参考：

| 我们的输入 | secid | 工作机制 |
|---|---|---|
| `000001` | `0.000001` | 启发式：代码以 `0` 开头 → SZ → 市场代码 `0` |
| `600519` | `1.600519` | 启发式：代码以 `6` 开头 → SH → 市场代码 `1` |
| `688001` | `1.688001` | 相同启发式：`6` → SH → `1` |
| `300750` | `0.300750` | 以 `3` 开头（非 6 或 8） → SZ → `0` |
| `830799` | `0.830799` | 启发式：代码以 `8` 开头 → BJ → 但 EastMoney 对 BJ 使用 `0` |
| `sh.000001` | `1.000001` | 显式 SH 前缀 → 市场 `1` |
| `sz.000001` | `0.000001` | 显式 SZ 前缀 → 市场 `0` |
| `bj.830799` | `0.830799` | 显式 BJ 前缀 → 但 EastMoney 对 BJ 使用 `0` |

重要提示：北京证券交易所在 EastMoney 系统中使用市场代码 `0`——
与深圳相同。区分由代码区间而非市场代码完成。

## Dolt 符号映射

Dolt 的 `investment_data` 数据库以带交换所前缀的格式存储符号。
这些前缀是规范标识符——在 `stock_daily.parquet` 的 `symbol` 列中、
数据库中以及面向用户的界面中：

| 符号 | 股票 |
|---|---|
| `SZ000001` | 平安银行 |
| `SH600519` | 贵州茅台 |
| `BJ830799` | 艾融软件 |

规范符号格式是唯一的输入/存储/查询形式——`strip_prefix` 类剥前缀逻辑已随
D9 从数据管线移除，前缀与代码永远在一起。

## 时间周期映射

Compass 在 GUI 和 CLI 中接受人性化的时间周期字符串。这些映射到
EastMoney 的数值 `klt`（K 线类型）参数：

| 用户输入 | klt | 语义 | 典型用途 |
|---|---|---|---|
| `1m` | `1` | 1 分钟 | 盘中 |
| `5m` | `5` | 5 分钟 | 盘中 |
| `15m` | `15` | 15 分钟 | 盘中 |
| `30m` | `30` | 30 分钟 | 盘中 |
| `60m`、`1h` | `60` | 60 分钟 | 盘中 |
| `1d`、`daily`、`day` | `101` | 日线 | 主视图 |
| `1w`、`weekly`、`week` | `102` | 周线 | 长期趋势 |
| `1M`、`monthly`、`month` | `103` | 月线 | 超长期 |
| （数字字符串） | 直通 | 原始 klt 值 | 用于测试 |

如果输入不匹配任何已知字符串，则原样直通。这支持直接的数值 klt
值（例如，`"101"` 被解释为 klt=101，日线）。

### 为什么是这些特定值？

EastMoney 的 klt 编号是其内部约定。`101`/`102`/`103` 分别对应
日线/周线/月线，是 EastMoney 的标准。分钟级别的值（1/5/15/30/60）更加直观。

### 数据模型中的时间周期

时间周期字符串在 CompassState 的 BarsMap 中用作组合键
`(symbol, timeframe)` 的一部分。这意味着你可以同时加载
`("SH600519", "1d")` 和 `("SH600519", "1w")`，在它们之间切换是即时的
（无需重新获取）。

## 综合示例

一个典型用户流程的完整符号转换过程：

```
用户打开 Compass。
配置设定：default_symbol = "SZ000001"，default_timeframe = "1d"

    "SZ000001" → 显式前缀 → 交换 "SZ"，代码 "000001"
    "1d"       → timeframe_to_klt → 101（概念上；数据在本地）

K 线数据在 DuckDB stock_daily 表中以键 ("SZ000001", "1d") 存储

用户输入 "SH600519"，点击提取。

    "SH600519" → 显式前缀 → 交换 "SH"，代码 "600519"
    从本地 Parquet 获取，缓存，显示。

用户输入 "sh.000001"，想要查看指数。

    "sh.000001" → 显式前缀 → 交换 "SH"，代码 "000001"
    获取上证指数而非平安银行。
```

GUI 输入框接受自由文本（裸码/前缀/名称均可搜索，D11），但选中/提交的
值一律规范化为带前缀的格式 `交换所 + 代码` 后查询本地数据库。
获取路径中没有网络往返。

## 决策记录

| 决策 | 选项 | 选择 | 理由 | 排除原因 |
|------|------|------|------|----------|
| 规范标识符：股票代码格式 | ts_code（`000001.SZ`）/ 裸六位码 / Dolt-native 前缀格式（`SZ000001`） | Dolt-native 前缀格式 | 前缀显式区分交换所，消除跨所碰撞（`SZ000852` vs `SH000852` 是不同行）；格式一致，均为一列 symbol | ts_code 混合身份与元数据，后缀格式不一致且解析需处理 `.` 分隔符；裸六位码无法区分 `000001`（平安银行 SZ）和 `000001`（上证指数 SH） |
| 交换所推断：如何从代码确定交易所 | 按代码前缀启发式规则 / 存储独立 exchange 列 / 要求用户手动选择 | 启发式规则：6→SH、8→BJ、其余→SZ（**⚠️ 已废弃，D9——仅作历史记录，输入层不再接受裸码**） | A 股代码区间不跨所：600xxx 必为沪市，300xxx 必为深市，8xxxxx 必为北交所；无需每行存储 exchange，减少冗余 | 存储独立列增加数据冗余且无实际收益；启发式对 000xxx 区间有歧义（股 vs 指），通过显式前缀 `sh.` 解决 |
| 歧义处理：000001 既可是股票也可是指数 | 不支持指数 / 默认选常见类型 / 显式前缀覆盖 | 默认 SZ（股票），显式前缀 `sh.` / `sz.` / `bj.` 覆盖 | 99% 使用场景是查股票，默认即可满足；极少数需要指数的场景用 `sh.000001` 显式指定 | 不支持指数会丢失功能；默认选指数会导致股票查询错误 |
| 输入层裸码禁令（D9，issue #181） | 接受裸 6 位码 + 启发式推断 / 只接受显式前缀输入 | 只接受显式前缀：`SZ000001`、`sh.000001`（dot 规范化）；裸码输入在 CLI `--symbols`、GUI 提交、`validate_symbol` 处一律拒绝 | 裸码 + 启发式在指数上不可靠（`000001` 股 vs 指）；输入层收口后全链路（数据/引擎/GUI/配置）格式统一，无歧义路径 | 保留裸码输入需在每处消费点重做推断，歧义风险与格式分裂无法根除 |
| 旧配置自动迁移（D10，issue #181） | 拒绝旧裸码配置启动报错 / 加载时自动迁移 | 加载 config 时检测裸码 default_symbol/watchlist，按旧启发式补前缀（6→SH、8/43/92→BJ、其余→SZ；dot 形式规范化）并回写文件；回写失败仅 warn 不阻断 | 旧配置文件（如 `default_symbol = "600519"`）无需用户手工改，升级平滑；内存默认值不迁移避免二次迁移 | 拒绝旧配置强制用户手工编辑，破坏向后兼容 |
| 搜索框语义（D11，issue #181） | 搜索也要求前缀 / 自由文本搜索 + 提交必须前缀 | 搜索框接受自由文本（裸码/前缀/名称），匹配时按 D11 公式规范化；仅选中/提交/同步值必须是前缀形式 | 用户可按裸码/名称快速搜索，同时 fetch 路径零裸码 | 搜索也要求前缀增加用户认知负担，且无法按名称搜索 |
| 指数代码剔除（ref #201） | 仅靠前缀区分（指数保留在数据中）/ import 时无条件剔除 6 个指数 | 6 个已知指数（SH000300/SH000852/SH000905/SH000906/SH000985/SZ399300）在 import 主查询与 symbol 枚举查询中 `NOT IN` 剔除 | 指数混入 `stock_daily.parquet` 会污染 SEPA 硬过滤（修复前 `MIN_AVG_AMOUNT` 实际线 300 亿元，top50 仅 2 只）；数据层剔除使所有下游天然无指数 | 仅靠前缀区分仍需各消费者自己过滤指数，且 SH000xxx 指数与 SZ000xxx 股票同号碰撞场景仍会误入 |
