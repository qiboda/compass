=== Finding 1 (BLOCKING) — parse_explicit_prefix panics on non-ASCII ===

File: crates/compass-core/src/data/symbol.rs (parse_explicit_prefix)
Root cause: byte-slicing code[..3]/code[..2] without char-boundary checks;
eq_ignore_ascii_case branches panicked ("end byte index 2 is not a char
boundary") on multi-byte UTF-8. New exposure: main.rs migrate_legacy_config
runs at every GUI startup over user-editable ~/.config/compass/config.toml —
default_symbol = "贵州茅台" (stock name pasted) crashed the GUI instead of
load_config's graceful-degradation contract.

FIX: code.get(..3)/code.get(..2) (Option — None on non-char-boundary →
treated as no prefix; length check subsumed by get). Return-slice safety
follows: get(..n) Some implies n is a char boundary.

RED evidence (before fix):
  $ cargo test -p compass-core parse_explicit_prefix_non_ascii
  thread '...parse_explicit_prefix_non_ascii_does_not_panic' panicked at
  crates/compass-core/src/data/symbol.rs:22:38:
  end byte index 2 is not a char boundary; it is inside '平' (bytes 0..3 of string)
  test result: FAILED. 0 passed; 1 failed
GREEN (after fix):
  test data::symbol::tests::parse_explicit_prefix_non_ascii_does_not_panic ... ok
  Assertions: ("平安银行") → ("", "平安银行"); ("贵") → ("", "贵");
  ("SZ平安") → ("SZ", "平安"); ("SH平") → ("SH", "平"). No panic anywhere.
